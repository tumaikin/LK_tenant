# VIS Tenant Portal

Статический прототип личного кабинета арендатора для публикации на GitHub Pages.

## Что внутри

- роли: арендатор, админ
- кабинет арендатора
- создание и просмотр технических обращений
- создание обращения сотрудником ресепшн от имени арендатора
- назначение исполнителя
- смена статусов
- комментарии и история
- mock-сценарий обращения из email
- разделы: договоры, платежи, уведомления, допуслуги

## Технология публикации

Проект переведён в полностью статический режим:

- без серверного рендеринга в рантайме
- без API route handlers
- без server actions
- без cookies и middleware
- данные и сессия хранятся в `localStorage`
- сборка публикуется как `out/` для GitHub Pages

## Локальный запуск

```bash
npm install
npm run dev
```

Локально сайт откроется на [http://localhost:3000](http://localhost:3000).

## Статическая сборка

```bash
npm run build
```

После сборки готовый статический сайт лежит в `out/`.

## GitHub Pages

В проект уже добавлен workflow:

- `.github/workflows/deploy.yml`

Что нужно в GitHub:

1. Создать удалённый репозиторий `LK_tenant`.
2. Запушить код в ветку `main`.
3. В настройках репозитория открыть `Settings -> Pages`.
4. Убедиться, что source настроен на `GitHub Actions`.
5. Дождаться выполнения workflow `Deploy GitHub Pages`.

Для Pages используется `basePath` репозитория `/LK_tenant`, он автоматически включается при CI-сборке через переменную `GITHUB_PAGES=true`.

## Важное ограничение

Так как это GitHub Pages, карточки заявок и прочие интерактивные данные работают как клиентский mock-режим:

- данные сохраняются в браузере пользователя
- новые заявки не уходят на сервер
- скачивание договора формируется в браузере как `.doc`

## Основные файлы

- `app/` — страницы интерфейса
- `components/providers/app-provider.tsx` — клиентский store и действия
- `lib/demo-store.ts` — seed, helpers и работа с `localStorage`
- `lib/types.ts` — доменные типы
- `data/demo-db.json` — исходные mock-данные
- `.github/workflows/deploy.yml` — деплой на GitHub Pages
